# Danang Apartments Bot

Telegram-бот + Mini App для поиска аренды жилья во Вьетнаме (Дананг, Нячанг, Хошимин, Ханой, Хойан)
с картой, фильтрами и автопарсингом Telegram-каналов. Вся схема ниже — **без единого платного
сервиса и без привязки банковской карты где-либо**.

## Компоненты

| Папка / файл                     | Что делает                                                                 |
|-----------------------------------|-----------------------------------------------------------------------------|
| `server/app.py`                   | Единое Flask-приложение: публичный API для Mini App, модерация, приём объявлений от скрапера, вебхук Telegram-бота |
| `scraper/scrape_telegram.py`      | Скрипт, читающий публичную веб-версию Telegram-каналов (`t.me/s/...`) и присылающий новые посты в API |
| `.github/workflows/scrape.yml`    | GitHub Actions — запускает скрапер каждые 5 минут, бесплатно и без сервера |
| `parser/extractor.py`             | Regex-разбор текста поста на цену/комнаты/город/тип жилья — черновик для модератора |
| `db/models.py`                    | Модели SQLAlchemy, общие для сервера и скрапера |
| `docs/`                         | Telegram Mini App — карта (Leaflet + OpenStreetMap), фильтры, карточка объявления с фотогалереей и ссылкой на оригинал |

## Как всё это работает вместе

```
Telegram-каналы (публичные)
        │  раз в 5 минут читает t.me/s/<канал> (просто HTTPS, без логина)
        ▼
GitHub Actions (scraper) ──POST /internal/ingest──▶ Flask-сервер (PythonAnywhere) ──▶ SQLite
                                                            │
                                     объявления в статусе "pending" ждут модератора
                                                            │
                          бот шлёт админу текст + кнопки ✅/❌ (Telegram webhook)
                                                            │
                                              approved ──▶ /listings API
                                                            │
                                        Mini App (GitHub Pages) запрашивает /listings,
                                        рисует метки на карте, открывает карточку по клику
```

## Почему именно так (без сервера и без карты)

- **Нет постоянно работающего процесса.** Обычный подход (userbot на Telethon, слушающий события в реальном времени) требует сервер, который "висит" 24/7 — это либо платный VPS, либо бесплатный, но с привязкой карты (Oracle Cloud Free и т.п.). Раз ни то, ни другое не подходит — вместо push-подписки на новые сообщения используется **опрос публичной веб-версии канала** (`https://t.me/s/<channel>`, доступна без логина и API-ключа) через GitHub Actions по расписанию. GitHub Actions бесплатен без ограничений по времени для публичного репозитория и не требует карты.
- **Задержка до ~5 минут вместо мгновенной.** Это единственная реальная плата за бесплatность: 5 минут — минимальный интервал для cron в GitHub Actions (и то часто с опозданием на пару минут из-за общей очереди у GitHub). Мгновенная доставка потребовала бы постоянного соединения, а значит — постоянно работающего сервера.
- **PythonAnywhere free — единственный сервис в схеме, который должен быть "всегда включён".** У него бесплатный тариф не требует карты и не "засыпает" (в отличие от Render/Railway/Fly, где бесплatный веб-сервис останавливается при простое). Ограничение — небольшая дневная квота CPU-времени и разрешён только 1 веб-сайт, поэтому API, модерация и вебхук бота объединены в одно Flask-приложение (`server/app.py`), а не разнесены на несколько сервисов.
- **Бот работает через webhook, а не через постоянный опрос (long polling).** PythonAnywhere free выполняет код только в ответ на входящий HTTP-запрос, без фоновых циклов — значит боту нельзя постоянно спрашивать Telegram "есть новые сообщения?". Вместо этого Telegram сам стучится на наш URL при каждом сообщении пользователя — это укладывается в модель "код выполняется по запросу" без изменений.
- **Карта — Leaflet + OpenStreetMap, не Google Maps.** Google Maps требует привязать карту к облачному проекту Google, даже если пользование остаётся в рамках бесплатного лимита. Leaflet + OSM не требует ключа вообще — визуально и функционально почти то же самое (метки, попапы, клик по объекту).
- **Mini App — статический сайт на GitHub Pages.** Тоже бесплатно без карты, отдаёт `docs/` как обычный сайт.
- **Facebook — без автопарсинга.** Facebook закрыл Groups API для сторонних приложений ещё в 2018 году, а скрапинг браузером нарушает ToS Meta и рискует блокировкой аккаунта — этот риск не стоит того при отсутствии платных обходных путей. Вместо этого: команда `/submit` в боте — пользователь/модератор копирует текст+ссылку+фото из Facebook вручную, дальше работает тот же regex-экстрактор и модерация.
- **Модерация перед публикацией.** Спарсенные объявления получают статус `pending`; админ подтверждает через инлайн-кнопки в боте, прежде чем объявление попадёт в `/listings` и увидит свет в Mini App. Так отсекаются дубли (одна квартира часто постится в 3-4 каналах) и потенциальные мошеннические посты.
- **SQLite вместо Postgres.** Меньше движущихся частей для бесплатного хостинга — файл лежит прямо на диске PythonAnywhere. Если проект вырастет, `DATABASE_URL` меняется на любую другую БД без переписывания кода (SQLAlchemy).

## Настройка с нуля

### 1. Telegram-бот
1. Создайте бота через [@BotFather](https://t.me/BotFather), сохраните `BOT_TOKEN`.
2. Узнайте свой Telegram user id через [@userinfobot](https://t.me/userinfobot) — это `ADMIN_TELEGRAM_IDS`.

### 2. Сервер (PythonAnywhere, бесплатно, без карты)
1. Зарегистрируйтесь на [pythonanywhere.com](https://www.pythonanywhere.com), тариф Beginner (free).
2. Загрузите код проекта (через Git-клонирование репозитория в консоли PythonAnywhere — доступ к github.com в бесплатном тарифе разрешён).
3. `pip install --user -r requirements.txt` в консоли PythonAnywhere.
4. Создайте `.env` из `.env.example` (`cp .env.example .env`) и заполните: `BOT_TOKEN`, `ADMIN_TELEGRAM_IDS`, три случайные строки в `ADMIN_API_TOKEN` / `INGEST_TOKEN` / `WEBHOOK_SECRET`, `DATABASE_URL=sqlite:////home/<youruser>/danang-apartments-bot/danang_apartments.db` (**четыре** слэша — это абсолютный путь), `API_BASE_URL=https://<youruser>.pythonanywhere.com`, `WEBAPP_URL` — HTTPS-адрес GitHub Pages (шаг 4).
5. Во вкладке **Web** → Add a new web app → **Manual configuration** → Python 3.10. Затем укажите Virtualenv `/home/<youruser>/.virtualenvs/<env>` и в WSGI-файле:
   ```python
   import sys
   path = '/home/<youruser>/danang-apartments-bot'
   if path not in sys.path:
       sys.path.insert(0, path)
   from server.app import app as application
   ```
6. Нажмите **Reload**, проверьте `https://<youruser>.pythonanywhere.com/listings` — должен вернуться `[]`.
7. Пропишите вебхук бота (один раз, из консоли PythonAnywhere):
   ```bash
   python scripts/set_webhook.py
   ```

### 3. Скрапер (GitHub Actions, бесплатно)
1. Запушьте проект в свой GitHub-репозиторий (публичный — тогда лимиты Actions не ограничены).
2. В настройках репозитория → **Secrets and variables → Actions**:
   - Secrets: `API_BASE_URL` (тот же, что на сервере), `INGEST_TOKEN` (тот же, что в `.env`)
   - Variables: `SOURCE_CHANNELS` (список каналов через запятую)
3. Workflow `.github/workflows/scrape.yml` запустится сам по расписанию раз в 5 минут; можно запустить вручную вкладкой Actions → Run workflow.

### 4. Mini App (GitHub Pages, бесплатно)
1. Settings → **Pages** → Deploy from a branch → ветка `main`, папка **`/docs`**. (GitHub Pages умеет отдавать только корень репозитория или `/docs` — поэтому папка называется именно так.)
2. В `docs/index.html` пропишите `window.API_BASE_URL` — реальный адрес сервера.
3. Полученный HTTPS-адрес пропишите в `.env` как `WEBAPP_URL` и нажмите **Reload** на PythonAnywhere. Telegram принимает в кнопке Mini App **только HTTPS** — с `http://` он отклоняет сообщение целиком, и бот выглядит «молчащим».
4. В [@BotFather](https://t.me/BotFather) → бот → **Bot Settings → Menu Button** укажите тот же URL.

## Как модерировать

Спарсенные и присланные объявления попадают в очередь со статусом `pending` и **не видны в Mini App**, пока модератор их не одобрит.

- `/pending` в боте — показывает самое старое непроверенное объявление с фото и кнопками ✅/❌
- после решения сразу подгружается следующее, так что очередь проходится без повторного ввода команды
- команда доступна только тем, чей Telegram id указан в `ADMIN_TELEGRAM_IDS`

## Тесты

```bash
python tests/test_e2e.py
```

Поднимает приложение на временной SQLite-базе с заглушками вместо Telegram API — ни сервера, ни сети, ни токена не нужно. Проверяет ingest ровно в том формате, который шлёт скрапер, CORS-заголовки, очередь модерации, фильтры и аутентификацию вебхука.

## Локальный запуск для разработки

```bash
pip install -r requirements.txt
cp .env.example .env   # заполните BOT_TOKEN хотя бы заглушкой для локального теста API
python -m server.app   # http://localhost:5000
```

Скрапер локально:
```bash
API_BASE_URL=http://localhost:5000 INGEST_TOKEN=... SOURCE_CHANNELS=danangrentaflat python -m scraper.scrape_telegram
```

Webapp — откройте `docs/index.html` через любой статический сервер (например `python -m http.server` из папки `docs/`), не напрямую файлом (иначе не сработают fetch-запросы к API).

## Telegram-источники

Скрапер читает публичную веб-версию канала (`https://t.me/s/<name>`). **Она существует только у каналов.** У групп/чатов такой страницы нет: `t.me/s/<name>` вернёт HTTP 200 со страницей участников и нулём постов, и источник будет молча простаивать. Проверка одна — открыть `https://t.me/s/<name>` в браузере: видны посты — скрапится, не видны — нет.

Проверено на момент настройки:

| Источник | Тип | Скрапится |
|---|---|---|
| `danangrentaflat` | канал, ~4300 подписчиков | ✅ да |
| `onewaydanang` | канал, виллы | ✅ да |
| `apartmentforrentdanang` | **группа**, ~2000 участников | ❌ нет |
| `vietnam_rent` | **группа**, ~6500 участников | ❌ нет |

Две группы из исходного списка убраны из `SOURCE_CHANNELS` — их содержимое доступно только через `/submit` вручную. Скрапер теперь явно пишет в лог, если источник не отдал ни одного поста, вместо того чтобы выглядеть как «новых объявлений нет».

Список редактируется в GitHub Actions variable `SOURCE_CHANNELS`, без изменения кода.

## Структура объявления

Каждое объявление всегда хранит `source_type` (telegram/facebook/manual) и `source_url` — ссылка
на оригинал, которая всегда показывается в карточке в Mini App. См. `db/models.py`.

## Что не реализовано в этой версии (следующие шаги)

- Подписки пользователей на сохранённые фильтры с push-уведомлением о новых объявлениях
- Веб-панель модерации (сейчас модерация полностью через бота — вполне рабочий вариант для небольшого объёма)
- Геокодирование адреса в координаты (сейчас `lat`/`lng` заполняются только если их вручную проставит модератор при редактировании объявления — Nominatim от OpenStreetMap умеет геокодинг бесплатно и без ключа, можно добавить вызов при одобрении объявления)
